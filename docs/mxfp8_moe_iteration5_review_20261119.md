## 2. Sol B: long single-global-pool router — first test an uncovered geometry

Own [flat routing search](../rtx/autotune/routing.py), its opening tests and, only if needed, the flat Sinkhorn execution/config/kernel path (`_routing_execution.py`, `_routing_autotune.py`, `routing.py`, `kernels/routing_sinkhorn.py`). Do not modify packed routing, affinity, metadata order, quota repair or solver iterations. In all **38 flat contexts / 152 observations** the first four trials retained the exact same forward **and** backward Sinkhorn geometry: 128 threads, row_groups=1, column_groups=4. At D384/K4 T16384, E32/E128 flat routers measured **3.359/4.699 ms** standalone. The E32 flat routing search trial 1→2 already improved **3.905→3.139 ms** while varying the hard configuration on unchanged Sinkhorn geometry. Retain access to that basin. Do **not** treat packed timing as the attainable global-pool time: they solve different routing problems.

**Ship first:** offer an existing *backward-only* column geometry on the same complete hard/metadata/forward plan as its control. Generate from legal group/thread choices using scheduled rows per worker, expert columns per group and CTA count vs device SMs; test more column owners before adding new kernels. At four column groups the current [flat kernel](../rtx/kernels/routing_sinkhorn.py) launches ceil(E/4)=8 or 32 column CTAs on 170 SMs and each column group scans all 16384 scheduled rows. Fewer groups increase CTAs but can hurt coalescing; measurements choose. Keep the actual four-trial opening usable (incumbent, useful hard alternative, its geometry challenger, retained alternative); demonstrate eight independent admissions on **T12288/D512/E48/K6/H256/S512 flat**. Preserve explicit priors and bounded progression. Keep packed T16384 as a no-change control.

If geometry cannot expose enough parallelism **and a paired component timing on one target shows column backward materially costs time**, try one sharded *global* column adjoint, based on the [existing segmented partial/apply algorithm](../rtx/kernels/routing_varlen.py), specialized to known global bounds. One FP32 partial per shard/expert, then reduce and apply to that shard's rows. Make the scratch compiler-visible and reusable across reverse iterations; never fake B independent sequences or allocate offsets inside the launch. Preserve history indexing, the incoming gradient and FP32 reduction. The existing flat launch key slices the first six token fields and cold selected backward uses its saved token: update keys, old-token compatibility, evaluator and bound/cold launches together for a new field. Do not introduce eager arithmetic or duplicate work that the public path won't use. Saved backward must not consult the current winner. This fallback changes summation order; require existing FP64 log-transport and score-adjoint gates, exact hard IDs/inverse, stable weights, every router scalar including near-cancelling gradients, and fixed-address changed input/dY replay. If only earlier traces of other shapes exist, label them accordingly: no profiler attribution of the 3.359/4.699 ms to the column adjoint is available here. Stop if the effect is in noise or gated out. Accept a reproducible **absolute** whole-step win for flat on MX and remeasure compact BF16 with that same router; this is shared infrastructure, not a native-FFN speedup.

## 3. Sol C: shared MLP — uncouple the long-reduction gradient grids

Own [ordinary MLP structural search](../rtx/autotune/mlp.py), its opening identity and focused MLP tests. Reuse [existing legal split families](../rtx/_bwd_search.py); no change to generic linear defaults, small-forward policy or kernel math. Across **all 48** fanout shared journals every one tried the prepared 8/8 gate/down dW + TMA down-store family. **None** tried unequal gate/down split counts or either count >8. Five tried any recompute-fusion + TMA down store. The long-shape opening crosses coupled 4/4 and 8/8 with stores; one-leg slots are not protected on an ordinary cold on-chip base. Adding more cold “prepared vs on-chip” proposals solves the wrong problem.

For the matched D384/K4/H320/E32/B16 shared-width triple S192/256/320, standalone MX vs checkpoint BF16 is **214.72/169.40, 236.11/224.52, 285.17/265.85 µs**. Recovering the entire deficits would save only **45.32/11.59/19.32 µs** *in that standalone comparison*. No whole savings forecast. For S192, changing the prepared store-family 4/4 trial 3 to 8/8 trial 4 takes shared objective **247.94→207.20 µs**. This suggests investigating partitions, not assuming doubling splits scales indefinitely. At S192/D384 current 128×128 dW tiles give 9 gate and 6 down output tiles: 8 splits launches 72 and 48 producer CTAs respectively before reduction. Increased parallelism competes with extra FP32 workspace traffic and another reduction workload.

**Ship first:** preserve a legal prepared, stored 8/8-equivalent comparison family generated by the existing tuner; derive one-leg alternatives from output tile count, available K panels, SM count and bounded workspace. Try the most underfilled leg with one more legal partition level, then the other or a different independent partition; compare to the *same* forward, backward preparation, stores, tiles and reducer. These are templates, not fixed 8/16 prescriptions. Bound the eight actual proposals; retain static/direct fallback, previous best family and exploration. No benefit just from measuring a candidate first. If partitions lose, one alternative is a same-store fused-gradient producer on the *strong* anchor, not the trial-7 direct/4+4 comparison; gate against the original BF16 rounding points and both independent scale orientations before considering it. Do not repeat hybrid-store or tiny-forward implementation work. Recheck S192 and a wider S512 control; reserve **B8×1536/D384/E32/K4/H320/S256** as the unseen long MLP workload (T12288). Measure ordinary shared F+B and whole packed step holding router and expert fixed; retain a small forward smoke. Accept only stable target benefit or leave the original opening unchanged. Do not trade a large workspace increase for an undetectable whole gain.
