# September 2026 correctness and release audit

The September 10 review identified gaps between the recorded release claims
and the implemented checks. The September 11 work uses the local RTX 5070 Ti,
driver 595.84, PyTorch 2.13.0+cu132, and the installed supported runtime.

## Fixes

- A failed confirmation now invalidates its candidate. Confirmation stops on
  the first failure, persists the failure, and propagates sticky CUDA faults.
  Previously a successful screen could hide a failed confirmation.
- Fused MXFP8 TMA rejects physical BF16 row strides not divisible by eight
  elements. The check uses the operand orientation: logical transpose changes
  the physical stride. Scalar loading still supports odd shapes.
- Transposed quantization rejects incomplete row tiles and incompatible
  `num_warps * quant_vec` partitions before compilation.
- NVFP4 GEMM rejects SMEM swizzles larger than the packed K-tile row.
- Specialized fused MXFP8 schedules reject register-decrease requests above
  the maximum possible initial CTA allocation.
- Specialized regional epilogues are quarantined after two/four-warp
  persistent candidates and an eight-warp fixed-grid candidate hung during
  runtime autotuning. Direct/fragment-register MMA epilogues remain exposed.
  One previously passing specialized-epilogue GPU test is explicitly skipped
  until the scheduling family is repaired. This is an
  implementation safety restriction, not evidence of poor performance.

These are legality and validation changes, not new quantization policies.
Kernel ABI revisions are unchanged; runtime winner loads already recheck
legality. Restart existing Python workers to load the new predicates.

## GPU localization

Saved fused-forward candidate `b11998c8e66d383838af`:

- M=33, N=511, K=257: reproduced mismatch, maximum absolute error 84.5.
- Same schedule at K=264: exact agreement with the baseline.

Saved backward candidate `d453e7e5e155545b558c`:

- M=96, N=1280, K=768, 16 quantizer warps: illegal instruction reproduced.
- Same schedule with eight quantizer warps: passes the FP32-reference gate.

These replays use fresh seeded inputs, not recovered original input tensors.
The replay utility records that distinction, configuration, shape, seed, and
source identity. Run each suspect candidate in its own process:

```bash
timeout 60s python benchmarks/replay_autotune_failure.py \
  autotune_datasets/blackwell_prospective_v3 \
  --config-id b11998c8e66d383838af \
  --output autotune_reports/tma_replay.json
```

Against all recorded v3 failures, the new predicates reject the configurations
behind 41 MXFP8 correctness failures, 26 compile failures, and one illegal
instruction. Sixteen NVFP4 correctness failures still need localization.
Static rejection is not a claim that every failed input was rerun.

## Qualification scope

The unified production matrix now includes aligned and ragged JIT-region
training/inference in eager and fullgraph-compiled modes, plus delayed
inference. It checks finiteness before relative errors and records source
hashes, validator hashes, runtime versions, arguments, and kernel revisions.
The final expanded matrix passed 49/49 cases after the legality changes:
`autotune_reports/review_20260911_production_final.json`.
The affected GPU suite passed 155 tests with one explicit quarantine skip and
137 subtests, with normal balanced-autotuning defaults enabled. The CPU suite
passed 241 tests (108 CUDA skips). Logs and diagnostic artifacts are kept under
`autotune_logs/review_20260911_*` and `autotune_reports/review_20260911_*`.

Representative remaining NVFP4 replays:

- Delayed `65c6430aff1fca565f57`, 33x511x257: mismatch reproduced (max absolute
  error 6.75). Changing only GEMM M atoms from eight to four does not change
  the mismatch, so this is not explained by that warp-layout coordinate.
- Fully packed `cfb10c20371b38032c43`, 32768x1280x1280: mismatch reproduced
  (max absolute error 40.375).
- Weight-prequantized `76a3e26864c39d8a71af`, 768x2560x1792: fresh seed-0
  replay passed exactly. This does not clear the historical failure on
  different inputs.

No tolerances were relaxed to accept those candidates, no dataset winners
were promoted, and no new latency/performance claims were made.

This does not qualify the other GPU SKUs or PyTorch 2.12.1, establish matched
training convergence, or establish production throughput targets. The 1.0
release gate remains open.
