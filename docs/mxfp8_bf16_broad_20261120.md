# MXFP8 versus BF16: broad whole-MoE comparison

## Result

On two HOME RTX 5090s, MXFP8 usually improves on **checkpointed BF16**, but
does not consistently beat **saved-intermediate BF16**. Wider projections
are more favorable; packed conservative capacity and tiny workloads remain
weaknesses. The earlier router improvements benefit both precision baselines.

Geometric means over seven primary architectures per layout; ratios are
BF16 time / MXFP8 time, so above one means MXFP8 is faster:

| Layout | Training forward | F+B vs checkpointed BF16 | F+B vs saved BF16 |
|---|---:|---:|---:|
| Flat | 1.147× | 1.127× | 0.993× |
| Independent packed pools | 1.103× | 1.099× | 0.930× |

For each metric BF16 uses the faster measured native/compacted layout. Raw
times for both layouts remain available; the compaction kernels are timed.
Tiny guards are excluded from these means. These are synthetic complete-layer
measurements, not transformer-training throughput or convergence results.

## Effort, controls and timing

- Dynamic BF16 inputs/weights, MXFP8 residual FFNs with recomputation; no PTQ,
  freezing, cached weight values or BF16 expert fallback. BF16 reference FFNs
  use ordinary BF16 GEMMs with FP32 activation/gating. The same selected FP32
  router, parameters, inputs and upstream are used by all precisions in a case.
- Primary expert/shared searches completed **32 unique eligible attempts**
  each. Flat routers completed 32. Packed routers admitted 20–21 before the
  90-second component deadline. Tiny guards completed eight per component.
  Affinity layout has its separate two-candidate qualification. This is not
  a model-wide budget of 32 calls.
- All 1,342 main-matrix residual observations were timing eligible, with
  no compile or correctness errors. Tuning is included in raw cold-cost fields,
  excluded from steady-state timing. Primary component tuning invocations
  totaled 156–207 seconds per context, separate from outer compilation/setup.
- Fullgraph/static `torch.compile`, aggressive supported Inductor options,
  default mode and `freezing=False`. Ordinary warmed outer CUDA-graph replay,
  three rotated visits × nine samples, batched CUDA events with at least 5 ms
  per sample. No profiler injection or optimizer update in the timed region.
  Forward is **training forward**, not no-grad inference.
- Main forward/whole-step sample relative MAD was at most 0.42%. Two standalone
  component phases drifted just over 5% across rounds; both are flagged in
  `analysis/summary.json`. Neither warning affects a main whole-layer ratio.
  Component times overlap and must not be summed into a whole-step estimate.

## Did the packed-router deadline hide a win?

The worst E96 packed case was additionally refined on a copy of its journal,
preserving its first 20 records and fixed expert/shared plans. Twelve extra
attempts completed its 32-trial router budget. Inputs, parameters, upstream,
affinity and fixed plans matched hashes; all qualification checks passed.

Whole time was **6.173 → 6.186 ms**, effectively unchanged, despite selecting
a different router configuration. The refined ratios were 0.949× checkpointed
and 0.825× saved BF16. These diagnostic results are not substituted into the
primary matrix or used to overwrite its capped observations.

Source-level explanation worth investigating: E96 flat schedules physical
capacity 1376 rows/expert; packed uses a conservative 1856-row shape bound.
The stronger BF16 reference compacts real work. Padding/useful-row efficiency
is a credible contributor, not a measured causal decomposition. More router
trials alone did not fix the observed gap.

## Numerics and scope

All **16 primary/guard runs plus the refinement** passed independent quantized
FP64 expert forward/input/weight/route-gradient checks, full-layer finite
checks, fresh-versus-graph replay and five-iteration stable live allocations.
Worst independent expert-oracle NRMS was **0.0131%**. Baseline compaction has
CPU output/all-gradient equivalence tests for saved and checkpointed modes;
the focused benchmark/baseline CPU suite passed 24 tests.
An additional CUDA check compared native/compacted saved/checkpointed BF16
outputs and every gradient on E96/D384 and E48/D768 packed cases: all eight
mode records passed. Worst nonscalar cross-layout NRMS was 0.0362%.

Versus BF16—not versus the quantized oracle—whole-output NRMS was 6.54–6.58%,
with cosine 0.99783–0.99786. Input-gradient NRMS was 6.57–6.59%. Every parameter
has descriptive RMS, absolute-error and cosine records in `numerics.csv` /
`.parquet`; near-zero scalar gradients should be judged by absolute error.
These are fixed random-fixture discrepancies, not a trained-model accuracy
claim. FP64 is only the correctness oracle, not the training baseline.

Two RTX 5090s, 170 SMs/32 GB each; Torch 2.13.0+cu132, CUDA 13.2, driver
595.99.02, CuTe 4.7.0. Runtime source digest
`b525f29dcc47c22b08863f05c51095c4522ea63f695e5125f5ec28f76664302e`.
Peak-memory fields are a shared-process high-water mark including setup,
not per-precision memory savings. No cross-SKU qualification is implied.

## Reproduction and artifacts

`autotune_reports/mxfp8_bf16_broad_20261120/` contains the frozen source,
environment, exact commands, per-case residuals/configurations/results, raw
samples, CPU tests, refinement and CSV/Parquet for timings/numerics/search.
Both GPUs were idle before the study and released afterward.

```bash
# Run each shard on a separate free GPU, using a new directory.
CUDA_VISIBLE_DEVICES=0 python -m benchmarks.compare_moe_precisions run \
  --output /path/to/results --shard 0 --trials 32 --seconds 90
CUDA_VISIBLE_DEVICES=1 python -m benchmarks.compare_moe_precisions run \
  --output /path/to/results --shard 1 --trials 32 --seconds 90
python -m benchmarks.compare_moe_precisions summarize --output /path/to/results
```

No performance implementation was changed for this comparison. The benchmark
adds a compacted **saved** BF16 control alongside the existing checkpointed one.
Next priorities supported by these results are packed useful-row efficiency,
thin FFN preparation/recompute cost and caller-aligned tuning—not a blanket
claim that 32 trials achieves 1.2× against either BF16 baseline everywhere.
